# 燕園手続きナビ

「北京大学留学ガイド（非公式・参考版）」の 45 記事を、**実際にやる順番の手続きチェックリスト**として引けるように再構成した単一ページ。

中国語版: [README.md](README.md)

公開先: https://claude.ai/artifact/JQCJtoGoowqnudPQcbUXbg

## なぜチェックリストなのか

note の目次式では読者が自分で絞り込む必要があり、次の 2 つが特に拾いにくい。

1. **身分によって答えが変わる** — 記事自身が「非学位生、学位生、予科生、本科生、大学院生でスケジュールが全く異なる場合あり」と明記している。
2. **手続きに隠れた依存順序がある** — 居留許可申請中はパスポートを預けるので、SIM と銀行口座はその前に済ませる必要がある。銀行口座には住宿登記表と中国の電話番号が必要。この順序は本文の一文に埋まっている。

そこで「ビザ / 住まい / プログラム」を選ぶと関係のない手続きが消え、各手続きに「先に必要なこと」を理由つきで出す形にした。

依存グラフの形は住まいで変わる（寮なら前台が住宿登記を代行するので SIM に依存しない。賃貸は自分でオンライン登録するため中国の電話番号が必要）。

## ビルド

入力となる `materials/`（取得した原文）はリポジトリに含めず、ビルド成果物のみを置いている。ゼロから再構築する場合は `write_inventory.py` / `fetch_note_assets.py` で原文を取得してから実行する。

```
python build_data.py    # api_export/<id>.json の本文HTML -> app/data/guide.json
python check_data.py    # 参照整合性と依存の循環を検査
python build_app.py     # template.html + retrieval.js.part + data -> app/index.html
python build_docs.py    # 代理サーバが引く server/docs.json（質問応答を使う場合）
python proto_retrieval.py   # 検索方式の検証（recall@k を出す）
```

### 本文は HTML から取る（text からは取らない）

`materials/inventory.json` の `text` は本文を行単位に潰したもので、note の
太字が独立した行になる。たとえば「本ガイドを参照したことにより発生した被害や
損害等について、本ガイド作成者は一切の責任を負いません」が 4 行に割れる。
この状態からは段落と箇条書きを区別できず、短い行を項目として扱うと一つの文が
4 つの項目に化ける。

そこで `materials/api_export/<id>.json` の `data.body`（元の HTML）を解析して
段落・箇条書き・見出しの構造を保ったまま取り出している。本文中に出てくる
タグは `p / li / ul / ol / h2 / h3 / strong / em / a / br / hr / figure /
figcaption / img / blockquote / table-of-contents` だけで、この範囲なら
`html.parser` による小さな変換で足りる。

- `h2` は `■` 見出し、`h3` は `▶` 見出しに対応する（従属関係は左罫で示す）
- `strong` は作者の強調意図なので残す（本文全体で 968 箇所）
- `<br>` で一段落に詰め込まれた `⚠️` `⭐️` の一言は独立した注記として切り出す（41 箇所）
- 授業時間割は元記事が note の数式機能（`\begin{array}`）で組んでいるため、
  生の LaTeX にならないよう行列に戻して表として組む（文字と並びは変えない）

インライン要素は `strong / em / br / a[http(s)]` のみに絞り、テキストは生成時に
エスケープしてから埋め込む。画面側はこれを `innerHTML` で流し込む。

### figure は画像の入れ物とは限らない

note は `<figure>` を画像だけでなく、添付ファイル・外部リンクカード・引用
（ポイント枠）の入れ物にも使う。138 個のうち 39 個は `<img>` を持たない。
一律に画像として扱うと、リンクと添付の中身が消えて「画像あり」の空枠だけが
残る（実際に一度そうなっていた）。`classify_figure` で中身を見て振り分ける：

| figure の中身 | 出力 | 件数 |
|---|---|---|
| `note.com/api/v2/attachments/download/` へのリンク | 添付ファイル（名前・サイズ・リンク） | 10 |
| `<img src>` | 画像、または図の枠とキャプション | 98 |
| `<blockquote>` | 中身の引用をそのまま残す | 3 |
| 外部リンク＋`<strong>`＋`<em>` | リンクカード（題名・ドメイン） | 25 |
| 空 | 捨てる | 2 |

引用はリンクを含むことがあるので、リンクカードより先に判定する（順序を逆に
すると「はじめに必ずお読みください」への案内がカードに化ける）。

### キー：値の箇条書きは二列に組む

元記事は月別の予定・窓口・費用を「時期：内容」の箇条書きで書いている。点を
打って並べるとキーと値が地の文に混ざるので、過半数が「キー：値」の形をして
いる箇条書きだけ定義リストに変える（116 箇所）。太字の位置が三通りあるので
`KV_FORMS` で吸収する。半端に一項目だけ変えると逆に読みにくいため、2 項目
以上かつ 6 割以上が該当する場合に限る。

また、段落まるごとが短い太字の行は、原文が h3 の下にもう一段の小見出しとして
使っているので見出し扱いにする（139 箇所）。長い強調文を巻き込まないよう
42 文字以下に限る。

### 画像は webp にして supporting file で配る

`assets` capability は宣言したページが organization-internal になり公開共有
できなくなるため使わない。代わりに必要な画像だけ webp に変換し、Artifact の
`files` で同梱して相対パスで参照する（同一オリジンなので CSP に掛からない）。
年間スケジュールの図は 1536×1024 のまま webp quality 82 で 249KB → 155KB。
読み込めなかった場合は `onerror` でキャプションだけの枠に差し替える。

出す画像は `IMAGE_EMBED`、出さない画像は `IMAGE_DROP` に URL で列挙する。

`app/index.html` は生成物。編集するのは `app/template.html` と `app/data/tasks.json`。

データは fetch ではなく `<script type="application/json">` に埋め込む。Artifact の CSP は同一オリジンでない fetch を黙って落とすため、埋め込みの方が読み込み失敗の余地がない。

## 資料の扱いの方針

- 本文は掲載時点の文章をそのまま収録する。要約・言い換えはしない。
- `tasks.json` の持ち物・費用・注意点は、記事本文に書かれている記述だけから組み立てる。本文に無い日付・金額・条件は追加しない。
- 各手続きに参照記事（`sources`）を必ず持たせる。`check_data.py` が空の `sources` をエラーにする。
- 記事間で記述が違う箇所はどちらかに決めず、`discrepancy` として両方を示す。

## note への導線は置かない

このページは note へ飛ばさない。`build_data.py` で次を落としている。

- **記事ごとの原文 URL**（`url` フィールドを出力しない）。記事の末尾にあった
  「note で元記事を開く」と「公開／更新」の行も画面から削除した。最終更新日は
  記事見出しの右に残している。
- **note のページへのリンク** 49 本（`strip_note_links`）。リンクは外して文字は
  残すが、リンク文字が URL そのものの場合は裸の URL が残るだけなので消す。
- **note 版の目次**（`nafe1e8c9b900`）。中身は 45 本すべてが note へのリンクで、
  このページには独自の分類ナビがあるため `EXCLUDE` で載せない。記事数は 45 本。
- **note 上での運用情報**（`DROP_TEXT`）。「✉️ 質問箱」「📨 クリエイターへの
  お問い合わせ」と「更新状況等」（PDF 版／note 版の作成履歴）。これらを指す
  「下記からご連絡ください」の一文も宛先がなくなるので落とす。

**添付ファイルのダウンロード URL（`note.com/api/v2/attachments/download/`）は
残している。** これは note のページへの遷移ではなくファイルの取得で、外すと
10 件の PDF・DOC が名前だけになって開けなくなるため。これも外す場合は
`NOTE_PAGE_LINK` の除外条件と `classify_figure` の添付判定を落とす。

出典表示は残している（`sourceName` / `sourceBy`）。リンクではなく文字だけ。

### 除外は項目ごとに判定する

`DROP_TEXT` をブロック単位で当てると、同じ箇条書きに並んでいる免責事項まで
一緒に消える（「はじめに必ずお読みください」の免責 5 項目と問い合わせへの
案内が一つの `ul` に入っており、実際に一度全部消えた）。`clean_blocks` では
箇条書きだけ項目ごとに判定している。

## 質問応答（自然文で引く）

### なぜ「まず検索」なのか

模型に渡せる入力は 64KiB まで（日本語なら約 21,000 字）。資料は 14 万字あるので
**全部渡すことはできない**。これは最適化ではなく前提条件で、必ず先に検索して
関係する小節だけを選ぶ必要がある。

### 検索は 2-gram の BM25（`app/retrieval.js.part`）

日本語は語の区切りが無いので、辞書を持たずに 2 文字単位で索引する。文書は
小節 525・手続き 27・用語 36 の計 588 件。これに二つ足している。

1. **同義語**（`app/data/synonyms.json`、手書き）— 「ケータイ」と資料の「携帯」は
   2-gram が全く重ならない。実測で「ケータイの料金は？」がタクシーのぼったくりと
   ATM の吞卡を上位に出していた。質問側に資料の言い回しを足して橋渡しする。
2. **内容語の完全一致**（`W_EXACT`）— 「中関新園」「居留許可」のような固有名詞は
   2-gram に割ると散る。実測で「中関新園に住みます」の 1 位が鉄道地図、2 位が
   中関園食堂だった。語がそのまま出てくる文書を別枠で押し上げる。

長い記事への罰も強めた（`B = 0.82`）。2.6 万字ある「9.1 その他情報・注意事項」が
何を聞いても上位に出てくるため。

`proto_retrieval.py` が同じ式の検証用で、手で正解を付けた 12 問での結果は
**recall@8 = 12/12、recall@12 = 12/12**（7 問は 1 位）。上位 12 件の分量は
2,566〜6,401 字で、64KiB の制約に対して十分な余裕がある。

小標本かつ自作の正解なので、これは「方式が成り立つ」証拠であって
「品質が検証済み」ではない。

### 引用を模型に作文させない

答えの根拠は `[S1]` の形で書かせる。この番号は**その質問で渡した資料にしか
振られていない**ので、模型は引用先を作れない。画面側は番号を実際の小節に
引き当ててから飛び先に変換し、範囲外の番号は点線の無効な印として見せる
（黙って通さない）。

### API キーはページに置けない

ページは全部ブラウザに落ちるので、キーを埋めれば誰でも読めて、そのまま他人に
使われる。加えて Artifact の CSP は外部 fetch を黙って落とすので、キーを晒す
覚悟をしても Artifact 上では繋がらない。だからキーを持つものを一段挟む。
それは**クラウドでなくてもよい**。

| | 用途 | キーの置き場所 |
|---|---|---|
| `server/local.py` | 手元で試す。Python 標準ライブラリのみ、Node 不要 | 環境変数（このプロセスだけ） |
| `server/index.mjs` | みんなに使わせる。FC 3.0 の **Web 関数** | FC の環境変数 |

両方とも同じ `rules.txt`（指示文）と `docs.json`（資料）を読む。

`local.py` はページも同じサーバから出すので同一生成元になり、CORS も CSP も
関係なくなる。`app/index.html` は `AI_ENDPOINT` を空のまま配り、`local.py` が
返すときに `/ask` を差し込む（生成物を 2 種類作らなくてよい）。

`AI_ENDPOINT` が空なら質問タブは検索だけで動く。検索層は接続先が無くても全員が
使えるので、自然文で資料を引く用途はこれで足りる。

手元の `local.py` では、上流（qwen3.7-plus）との往復と SSE の流し込みまで実際に
動かして確認した（2026-09-17）。通したのは経路であって、答えの中身の評価は別途
（「未収録・未実装」を見る）。

配備手順・濫用対策・実測した範囲は [`server/README.md`](server/README.md)。
資料を更新したら `python build_docs.py` で代理側の資料表も作り直す。

## 見た目について

**大学の校章は使わない。** ページは「非公式」と明示しているので、大学の標章を
載せると見た目が学校公式の制作物のように読めてしまい、自分の但し書きと矛盾する。
代わりに燕園の目印として**博雅塔**の線画（インライン SVG、`.mark`）を題名の左に
置いている。これは地標の絵で、機関の標章ではない。

燕園紅（`--accent` = `#8E1B18`）を効かせるのは題名・塔の印・段の番号・条件
バッジ・リンクだけに絞る。ダークテーマでは `#E98A84` に持ち上げる。

## レイアウトの方針

タブごとに幅と並べ方を変えている。一律に多段組みにはしない。

| タブ | 幅 | 並べ方 | 理由 |
|---|---|---|---|
| 手続き | 全幅 1120px | 概要は横並びのグリッド、段は縦積みのブロック | **手続きは順番が中身**。段を左右に割ると読む順が Z 字になって前後関係が壊れる |
| 資料 | 880px | 分類チップで絞り込み＋単列 | 本文は読み物なので 66ch 以内。12 分類を縦に積むと後ろの分類まで遠い |
| 用語集 | 全幅 1120px | `auto-fill` のカードグリッド | 語は短く順番もないので敷き詰めるのが素直 |
| 質問 | 880px | 単列 | 答えと引用元を読むところ |

タブは 手続き / 資料 / 用語集 / 質問 の 4 つ。「このページについて」タブは
作者の指示で削除した。非公式である旨は題名横のバッジと、「資料 > ガイドについて >
はじめに必ずお読みください」（免責 5 項目）が担っている。

段（phase）は見出し帯つきのブロックにした。地の色は `--ground`（ページと同じ）で、
中の手続きカードが `--surface`。`--surface-2` を地にすると、明るいテーマでは
カードが浮くがダークテーマでは地のほうが明るくなって逆転するため、この組み合わせに
している。

手続きタブの先頭に概要ブロックを置き、進捗・**次にやること**・段ごとの進み具合を
出している。「次にやること」は未完了で前提もすべて済んでいる最初の手続きで、
長い一覧を上から探さずに済む。段のセルを押すとその段へ飛ぶ。

## 内容が重なっている記事

「📅 年間スケジュール（燕園校区／本部）」と「📅 新入生留学スケジュール」は
扱う範囲が重なる。重なっている項目：寮予約、ビザ申請、航空券、报到、履修登録、
期末試験、修了手続き。

役割は別なので統合はしていない。年間＝毎年くり返す学年暦、新入生＝出願から
修了まで一度だけ通る流れ。ただし読者がどちらを見ればよいか分からないため、
`EDITOR_NOTES` で各記事の先頭に案内を出している（原文ではないので点線枠で
区別する）。手続きの持ち物と前後関係は「手続き」タブが持つので、新入生
スケジュールの内容はそちらとも重なる。

元記事側で整理するなら、新入生スケジュールから年間の学期日程を落として
年間スケジュールへのリンクに置き換えるのが素直。

## 未収録・未実装

- PDF / DOC 添付 10 件（学費基準、保険の説明、居留許可の申請書テンプレートなど）は、
  名前・サイズ・ダウンロードリンクだけ出している。**中身は読み取っていない**ので、
  ファイル名から内容を推測して答えてはいけない。`materials/unread_attachments.json` 参照。
- 画像 93 箇所は、図があった位置とキャプションだけを残している（画像本体は note の
  外部ホストにあり Artifact の CSP では読めない）。地図・フロー図・スクリーンショットの
  中の文字は読めない。同梱しているのは 5 枚（年間スケジュール、X1 / X2 ビザと
  居留許可の見本、X1・X2 と居留許可の関係）で、他の図が必要なときは作者側で `IMAGE_EMBED` に
