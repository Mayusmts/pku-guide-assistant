# 燕园导航

**给赴北京大学留学的日本学生用的入学办事助手。** 从拿到录取通知到办完居留许可，这段时间要跑的手续又多又有先后顺序，一旦弄反就得重来。这个页面把这些事按实际要做的顺序理清楚，并且只显示跟你有关的部分。

界面语言为日语（面向日本学生），中文的机构名、手续名保留原文。

## 四个部分

| | 内容 | 规模 |
|---|---|---|
| **手续清单** | 从渡航前到结业，按 7 个阶段排列的办事流程。选完「签证 / 住处 / 项目」后不相关的手续消失，每项列出必须先办完的前置条件和理由，可勾选记录进度 | 27 项手续・21 条依赖 |
| **资料** | 学校与留学生活的相关信息原文，按 12 个分类浏览，也可关键词检索 | 45 篇・525 小节 |
| **术语表** | 中日对照词表。办手续时窗口只说中文（报到、住宿登记、体检、居留许可……），查得到对应的日语说法 | 36 条 |
| **Agent** | 用日语自然提问，从上面全部内容里检索后作答。每句话带编号，点一下跳回原文核对 | 检索 588 条 |

前三项不需要联网服务也能用；Agent 需要接一个持有 API 密钥的服务端（见下方运行说明）。

## 一、解决了什么问题

北大留学在入学前后要办 **27 项手续**。难点不在"找不到资料"，而在两处：

**1. 哪些手续跟你有关，取决于你的身份。** 原文自己就写明「非学位生、学位生、预科生、本科生、研究生的日程可能完全不同」。读者得先自己做一遍筛选。

**2. 手续之间藏着先后顺序，而这个顺序只作为正文里的一句话存在。**

最典型的一条链：

```
居留许可申请  ← 住宿登记表、体检证明、学费缴清（必需材料）
              ← SIM 卡、银行卡 ······ 申请期间护照要上交，必须先办完

银行开户      ← SIM 卡（短信验证需要中国手机号）
              ← 住宿登记表（必需材料）
              ← 学生证（在学证明）

住宿登记      ← 已入住（住处确定）
              ← SIM 卡（在线登记需要中国手机号）
```

顺着读下来：要办居留许可，得先有银行卡；要办银行卡，得先有住宿登记表和学生证；要办住宿登记，得先有手机号。**四层深。**

而在原文里，最关键的那一环只是一句话：「申請中はパスポートを預けるため、先に済ませておく必要がある」（申请期间护照要上交，因此需要事先办完）。

顺序错了的代价是真实的——护照被收走的那两三周里，卡办不成，或者整轮手续要重跑。

所以这个作品不是"指南搜索"，而是**把隐式的依赖关系显式化**：选完「签证 / 住处 / 项目」三个条件后，不相关的手续消失，每项手续下面列出前置条件并附上理由。

依赖图的形状还会随住处变化——住宿舍的话前台代办住宿登记，所以不依赖 SIM 卡；租房需要自己在线登记，因此必须先有中国手机号。

## 二、如何拆解任务、与 AI 协作

拆成四段推进，每段的产物都能被单独检查，不把"一个大任务"整个交出去：

| 阶段 | 产物 | 分工 |
|---|---|---|
| 取材 | 45 篇正文 HTML + 109 个素材 | AI 写抓取脚本；我定「取 HTML 不取纯文本」 |
| 结构化 | `guide.json`：525 个小节、9 种内容块 | AI 写解析器；我逐类核对结果，挑出原文里的特例 |
| 建模 | `tasks.json`：27 手续 / 21 条依赖 / 36 术语（**手写**） | 我从正文整理依赖和理由；AI 只做格式与引用校验 |
| 交付 | 单文件页面 + 两套服务端 | AI 写实现；我定架构约束 |

协作上有一条全程坚持的规矩：**AI 不许补原文里没有的信息。**

`tasks.json` 里每条携带物品、费用、注意事项都必须能在原文定位；构建时 `check_data.py` 强制每项手续挂上出处，挂不上直接报错、构建失败。这条规矩把"模型顺手编一个看起来合理的数字"——这类最难被发现的错误——挡在了构建阶段，而不是等用户按着错误信息跑一趟才发现。

## 三、哪些关键判断由我完成

我做的是产品判断，不是具体实现。

**决定做「顺序」，而不是做「搜索」。** 拿到这批资料，最直觉的做法是套一个问答机器人，问什么答什么。但我自己看下来，真正会让人出事的不是"找不到"，而是"顺序搞错"。所以主界面定成了一份带前后顺序的清单，而不是一个搜索框。问答是第二入口，不是主角。

**给 AI 划了一条红线：原文没写的，一个字都不许补。** 这类信息一旦编错，用户是真的会白跑一趟。所以宁可不写，也不猜。

**要求答案必须能点回原文。** 用户没有理由无条件相信一个 AI。所以每句话后面都带编号，点一下直接跳到它依据的那一段，让人自己核对。技术上这个编号只在本次检索命中的段落上存在，模型无法伪造；对不上的编号会显示成无效标记，而不是默默放过。

**资料里没有的，必须说「不知道」。** 明确要求它在查不到时老实回答「提供された資料では確認できません」，并指出缺的是哪一项，而不是顺着话头编一个听起来合理的答案。

**不放学校校徽。** 页面已经写明是非官方的，再放校徽会让人误以为是校方出品，和自己的声明打架。改用燕园的地标（博雅塔）线描——那是地标，不是机构标识。

**不放通往原文平台的外链。** 保留来源署名，但不做导流入口，避免读者误以为这是原作者的官方产品。

## 四、如何验证最终结果

做到的和没做到的都列出来。

### 已验证

**每一条都查得到出处。** 构建时自动检查每项手续有没有挂上来源、依赖关系有没有互相打转、引用的文章是否真实存在。挂不上就直接报错、构建不出来。目前全部通过：

```
$ python check_data.py
✅ 整合性エラーなし
```

**该找到的能不能找到。** 我出了 12 道真实场景的日语问题（例如「手机什么时候办」「住宿登记要带什么」），先人工标好正确答案，再看系统找不找得到：

```
$ python proto_retrieval.py
=== recall@k（正解の記事が上位 k 件に入るか） ===
  k=4   11/12   取れず: 中関新園に住みます。入寮のとき何を確認すればいいです
  k=8   12/12   全問命中
  k=12  12/12   全問命中
```

12 题全部落在前 8 条结果里，其中 7 题排第 1。

**整条路真的跑通了。** 本地服务接 qwen3.7-plus 实际提问，上游往返与 SSE 流式返回都验过（2026-09-17），答案能带着可点击的引用返回，不是只有界面。

**输入边界逐项实测。** 空问题→400、超长→413、未知 id→400、密钥未配→500。

### 尚未完成（不夸大）

- **答案质量的系统评测还没做。** 上面那 12 道题样本小，而且正确答案是我自己标的，只能说明方法成立，不能说明质量过关。验收集已设计好 20 题（含 3 题资料缺失、3 题条件不明、2 题来源冲突、2 题范围外），见 `MATERIALS_REVIEW.md`，但尚未执行。
- **云端部署侧未验证。** 目前只验过本地服务，`index.mjs` 没有实际运行过。
- **没有真实用户数据**，因此不声称任何满意度或办事成功率。

## 技术实现概要

| | |
|---|---|
| 前端 | 单文件 HTML，零框架零依赖。数据内嵌而非 fetch（Artifact 的 CSP 会静默丢弃跨源请求） |
| 检索 | 手写 2-gram BM25，588 个文档，纯 JS 跑在浏览器里。日语没有词边界，2-gram 免去分词器 |
| 问答 | 前端只发小节 id，正文和指令都在服务端——页面替换不了喂给模型的资料 |
| 服务端 | 两套等价实现：`local.py`（纯 Python 标准库）／`index.mjs`（阿里云函数计算 Web 函数） |
| 数据管道 | Python 标准库 `html.parser` 手写的解析器，把正文 HTML 还原成结构化内容块 |

详见 [TECHNICAL.md](TECHNICAL.md)。

## 构建与运行

构建的输入 `materials/`（抓取来的原文）不随仓库分发，只提交构建产物。要从头重建，先用 `write_inventory.py` / `fetch_note_assets.py` 取回原文。

```bash
python build_data.py     # 正文 HTML -> app/data/guide.json
python check_data.py     # 检查引用完整性与依赖是否成环
python build_app.py      # 模板 + 数据 -> app/index.html
python build_docs.py     # 服务端查表用的 server/docs.json
python proto_retrieval.py    # 检索验证，输出 recall@k
```

本地试用问答（无需 Node）：

```powershell
$env:DASHSCOPE_API_KEY  = "sk-..."
$env:DASHSCOPE_BASE_URL = "https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1"
python server/local.py
```

打开 `http://127.0.0.1:8787/`。不配密钥也能用，只是没有 AI 回答那一栏，检索照常工作。

部署步骤见 [`server/README.md`](server/README.md)。
