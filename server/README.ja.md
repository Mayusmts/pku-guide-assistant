# 質問応答の代理サーバ

画面（`app/index.html`）から質問を受け、資料を添えて千問（アリババクラウド百煉）に
投げ、答えを SSE で流し返す。

中国語版: [README.md](README.md)

## なぜ代理を挟むのか

**API キーをブラウザに置けない。** それだけなら単純な転送でも足りるが、転送だけだと
画面側から指示文と資料を好きに差し替えられ、他人の用途の無料 LLM 代理として使われる。
そこで役割をこう分けている。

| | 持つもの |
|---|---|
| 画面側 | 検索（どの小節が関係するか）だけ。送るのは **質問・利用者の条件・小節の id** |
| 代理側 | API キー、資料の本文（`docs.json`）、指示文（`RULES`） |

画面は id しか送れないので、資料に無い文章を模型に読ませることができない。
指示文も差し替えられない。

## まず手元で動かす（Node 不要）

`local.py` はページと代理を同じサーバから出す。同一生成元になるので CORS も
Artifact の CSP も関係なくなり、キーは**この プロセスだけ**が持つ。Python の
標準ライブラリだけで動く。

PowerShell:

```
$env:DASHSCOPE_API_KEY  = "sk-..."
$env:DASHSCOPE_BASE_URL = "https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1"
python server/local.py
```

→ `http://127.0.0.1:8787/` を開く。起動時にキーの有無が出る（下 4 桁だけ表示。
キー全体はどこにも書き出さない）。待ち受けは `127.0.0.1` 固定で、LAN に出すには
`--host` を明示する必要がある。

`app/index.html` は `AI_ENDPOINT` が空のまま配れるようにしてあり、`local.py` が
返すときに `/ask` を差し込む。だから Artifact 版とローカル版で別の生成物を
作らなくてよい。

キーを設定せずに起動しても検索タブは普通に使える（AI の欄だけ出ない）。

## 組み立て

```
npm run build:docs     # プロジェクト直下で python build_docs.py
```

`server/docs.json`（588 件・約 476KB）は `app/data/guide.json` と
`app/data/tasks.json` から生成する。画面側の検索と同じ単位・同じ id なので、
前後で資料がずれない。**資料を更新したら必ず作り直す。**

## 環境変数

| 名前 | 説明 |
|---|---|
| `DASHSCOPE_API_KEY` | 百煉（Model Studio）の API キー |
| `DASHSCOPE_BASE_URL` | `https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` |
| `MODEL` | 既定 `qwen3.7-plus` |
| `ALLOW_ORIGIN` | 配備したページの生成元。既定 `*`。**本番では必ず指定する** |

`WorkspaceId`（业务空间 ID）は百煉のコンソールで確認する。
**API キーは作成したリージョンの `base_url` と組で使う**（北京で作ったキーを
東京の base_url には使えない）。リージョンは利用者の居場所で選ぶ：
在学中は北京（`cn-beijing`）、渡航前の日本からが多いなら東京（`ap-northeast-1`）。

## 配備（アリババクラウド関数計算 FC 3.0）

**必ず「Web 関数」として作る。** SSE の流し込みに対応するのは Web 関数だけで、
イベント関数では流れない（答えが出るまで無反応になる）。

1. ランタイム Node.js 20 以上、**Web 関数**を選ぶ
2. `server/` の4ファイル（`index.mjs` / `docs.json` / `rules.txt` / `package.json`）を上げる
   —— `rules.txt` が無いと起動時に指示文を読めず落ちる
3. 起動コマンド `node index.mjs`、リッスンポート `9000`
4. 上の環境変数を設定する
5. HTTP トリガーを付け、認証なし（`anonymous`）で公開する
6. 払い出された URL を `app/template.html` の `AI_ENDPOINT` に入れ、
   `python build_app.py` で作り直す

確認：`curl <URL>/health` が `{"ok":true,"configured":true,...}` を返せばよい。

`index.mjs`（Node 版）と `local.py`（Python 版）は同じ `rules.txt` と
`docs.json` を読むので、指示文と資料は一箇所で管理できる。手元で試すのは
`local.py`、みんなに使わせるのは `index.mjs` を FC に置く、という使い分け。

## 入力の制限（濫用対策）

- 質問は 400 字まで、本文全体で 8KB まで
- 小節 id は 20 件まで、`docs.json` に無い id は捨てる
- 資料の分量は 12,000 字で打ち切る（体检の全国保健中心一覧だけで 3,000 字ある）
- 同一 IP から 1 分 20 回まで

**この連打止めはメモリ上なので気休め**。FC は実例が複数立つと別々に数える。
本気で絞るなら API ゲートウェイか WAF 側で行う。公開範囲を広げる前に、
`ALLOW_ORIGIN` の指定と合わせて必ず見直すこと。

## 答えの作り方（`RULES`）

資料そのものの性質から来る制約を指示文に固定してある。

- 渡した資料だけで答える。無ければ推測せず「提供された資料では確認できません」
- そのうえで、近い情報があれば案内する（作者の意向：*相関情報や記事は出してよいが、
  確証のない情報は出さない*）
- 根拠の番号 `[S1]` を必ず付ける。**画面側は渡した番号しか飛び先に変換しない**ので、
  模型が引用元を作文できない。範囲外の番号は点線の無効な印として見えるようにしてある
- 非公式であることを断定表現にしない
- 費用・日付・窓口時間は資料の時点の情報だと添える
- 資料間で食い違うときは両方示す（住宿登記の URL など実際に食い違いがある）
- 利用者の条件（ビザ／住まい／プログラム）で変わる手続きは条件に合わせる

`temperature: 0.2`。手続きの話で言い回しが揺れても得がない。

## 確かめたこと / まだのこと

`local.py` はこの環境で起動して、次を実測した。

- `/health` が資料 588 件を読めている
- `/` がページを返し、`AI_ENDPOINT` に `/ask` が差し込まれる
- 入力の検証：空の質問→400、400字超→413、未知の id→400、id なし→400
- キー未設定→500 `unauthorized`
- 連続投入で keep-alive が壊れない（本体を読み切る前に応答すると接続リセットに
  なるため、`_drain` で必ず読み捨ててから返している）
- プロンプトの組み立て（利用者の条件・資料番号・更新日が入る）
- **上流（qwen3.7-plus）との往復と SSE の流し込み**（2026-09-17）。キーを
  環境変数に入れて実際に質問し、答えが流れて返るところまで動かした。

**まだのこと。**

- **`index.mjs`（Node 版）は実行していない。** この環境に Node が無く、
  構文の目視確認までしかしていない。FC に上げたら `curl <URL>/health` で
  `configured:true` を確かめる。
- **実際の応答品質を測っていない。** 検索側は 12 問の手作り評価で recall@8 = 12/12
  だが、答えの正しさ・引用の妥当性・「分からない」と言うべき場面で言えるかは未評価。
  公開前に `MATERIALS_REVIEW.md` の受入基準（資料欠落・条件不明・出典衝突・範囲外を
  含む設問）で通すこと。
- 費用（トークン課金）の実測。
